## 2. **修掉一个自己造成的覆盖事故**（本轮最该记的一条）

t199 那组样盘的键名按字母顺延（`"ABCDEFGH"[i+3]`），t201 这组又用了 `"DEFGH"[i]`
→ **键名相撞**：新一轮把 t199 的 **3 张八字盘与 1 张紫微盘覆盖掉了**。

**表现是验证深度不升反降（85% → 77%）**——正好被这个指标当场抓住。
（若只看覆盖率，什么都看不出来：覆盖率从头到尾都是 49.9%／67.7%…）

修法：键名改成描述性且不可能相撞的 `cov1_<art>_<n>` / `cov2_<art>_<n>`。
修完 depth 升到 **90%**，t199 的盘也都回来了（bazi 171 → 187）。

顺带查明：t199 的奇门组从 `D` 起，**没有**撞掉 `caseC` 的「反吟局」盘；
紫微 `caseC` 的运限盘也保住了。

## 3. 新增：取值域检查

`tools/domain-check.py`（＋`test-domain-check.py`，均已入 CI）。

**查什么**：谓词写了 `{key: X, value: v}`，而 `X` 是**封闭值域**键、`v` 又不在值域内
→ 这条谓词**永远不可能命中**（死谓词），**但覆盖率照旧把它算成「已映射」**。

**既有门禁都不查这一段**：

| 检查 | 覆盖 | 不覆盖 |
|---|---|---|
| `--check-art-keys` | 键是否在该术产出 | 取值 |
| `--check-open-values` | **开放**值域键的取值是否在样盘出现过 | 封闭值域的取值 |
| 死引用扫描 | 键是否在样盘出现过 | 取值 |

**实跑结果：0 处越域** —— 全库干净。

### 3.1 一个被我误判、值得记下的细节

我先入为主以为 `rizhu` 是「日柱」（六十甲子），于是把穷通宝鉴那批 `{rizhu: 乙}` 当成缺陷。
查引擎才发现：`emit.ts` 是 `pushFact(out, "rizhu", input.dayGan, …)` ——
**`rizhu` 是日干，值域是十天干**，那批谓词**是对的**。

所以这个检查用的是**词表里声明的值域**（由引擎 `toFactVocabJson()` 生成），
**不是我的记忆**；测试里也把这条钉住（`rizhu` 值域＝10）。
