# 《三命通会》010：甲日戊岁例的条件式作用阶梯

此交付只把《论太岁》[L1081–1083](../../sources/fulltext/bazi/sanming-tonghui/fulltext.md#L1081) 已说出的**条件式步骤**写成可核验合同。完整 `SANMINGTONGH-010` 仍为 `blocked`，`applicable_to=[]`、`verified=false`；本步骤不进入六主题规则包，不把文本中的“吉／凶”当现实事件预测。机器可读定义见[合同 JSON](SANMINGTONGH_010_CONDITIONAL_EFFECT_CONTRACT_20260923.json)。

## 来源范围与输入

入口仅为本命**甲日**遇**所选戊流年**。当生太岁与逐年游行太岁不同；同一事实袋即使含其它戊年，也不能代替所选年份。其它日干／岁干组合是本例“不适用”，不能据此判完整 010 不成立。

来源先把甲木克戊土称作“日犯岁君”，再分两项：原局或当年有效大运确能**制伏甲木，使其不能克戊**称“有救”；原局或当年有效大运的癸与该戊岁**相合有情**称“有情”。这两个输入均取 `proven / ruled_out / undetermined`。`proven` 必须有独立作用证据；`ruled_out` 必须完整扫描原局及所选年份有效大运的相关通道并明确排除；缺键、只见结构、资料冲突或只扫描一部分均为 `undetermined`。大运须是该年有效柱，不能在整个人生大运列表中任选一个。

现有 `named_rescue_evidence_coverage` 仅扫描同柱庚申及癸戊合的具名**结构线索**。它既不能产 `proven`，也不能产 `ruled_out`：庚申／庚辛的制伏强度和受扰情况未定义，大运中其它有效制伏路径未穷尽；同书[《论十干合》L1118](../../sources/fulltext/bazi/sanming-tonghui/fulltext.md#L1118)又称戊癸“无情之合”，不能把一般合名直接当作本例“有情”判据。若未来独立审读明确本段与通用合名的优先级及盘面条件，才可产这两个语义输入。

## 来源已给出的条件式步骤

下表仅在甲日、所选戊年及两个语义输入**均已独立裁定**时运行。表中的 `ruled_out` 不是“没有看到庚申／癸”的缩写。

| 有救 | 有情 | 原文层的分级 |
|---|---|---|
| `proven` | `proven` | 凶反为吉 |
| `proven` | `ruled_out` | 凶半 |
| `ruled_out` | `proven` | 凶半 |
| `ruled_out` | `ruled_out` | 凶莫能解 |
| 任一 `undetermined` | 任意 | 信息不足 |

“两项、一项、零项”按原文相邻的“有救／有情”两类来实现，是本合同的**局部解释**，只限甲日戊岁例，不向其它干支推广。即使入口已满足，语义输入未裁定也不能输出凶半或凶莫能解。来源出现的“其年反必为财”等判语未纳入此阶梯：其适用及现代六主题映射未裁定。

## 真实盘与验证边界

两仓共享的十个 `caseP1_010_*` 是实际日期排出的事实袋。`both`、`same_only`、`split_only`、`split_and_gui`、`natal_gui_only`、`luck_gui_only`、`neither`、`unknown_luck` 在所选 2018 年满足**入口**；`wrong_day` 和所选 2017 年的 `wrong_year` 不满足入口。其中 `neither` 只表示未见两项具名线索，不是“无救”；`unknown_luck` 缺当年有效大运，更不可能排除救应。**十盘都没有经过独立作用裁决，作用阶梯全部是信息不足或不适用；没有真实作用满足／反例样盘。**

运行 `python3 tools/verify-sanming-010-conditional-effect.py` 将核对源文 SHA-256、五处逐字锚点、十个真实盘入口／非入口，以及九种**合成输入状态**的阶梯真值表。合成输入只验证原文条件句的执行，不充当真实盘作用证据。完整 010 的下一步是裁定“制伏纯粹”的力量、位置、干扰与大运取法，以及本段戊癸“有情”相对《论十干合》的限定，随后形成至少一个真实盘的有救／有情正例、完整排除反例和缺键盘；在此之前不得把本合同升格到 `rescue_condition`、`transit_effect_semantics` 或主题规则。
