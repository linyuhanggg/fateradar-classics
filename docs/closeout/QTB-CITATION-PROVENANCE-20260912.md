# 调候救应 76 条的**引文出处**复核（2026-09-12，队长实测）

> 起因：准备按 `RESCUE-LABEL-AUDIT-20260912.md` 第二问的「76 条调候救应待实现」动手实现，
> 动手前先核一件事——**那 76 条的「逐字引文」是否真的在本条（该规则）自己声明的来源里**。
> 结论：**大多数不在**。故先把这件事记下来，实现暂停在「引文出处补齐」之后。

## 1. 方法与分母

- 底表：`RESCUE-LABEL-AUDIT-20260912.md` 逐条结果表的 **76 行 `QTB-*` `has_rescue`**（机械提取，未手抄）。
- 原文：`sources/fulltext/bazi/qiongtong-baojian/fulltext.md`（1,824 行；奇数行为正文段，偶数行空行）。
- 「本条的来源」＝该规则 `sources[].start_line..end_line` 的并集（`references/executable/qiongtong-baojian.json`）。
- 比对口径：去标点空白后做**子串包含**；命中即「引文在本条已声明段落内」。
- 「月令段」＝正文里由 `(三春|三夏|三秋|三冬|若干月)＋日干＋五行` 起首的分组标记，从该标记到**下一个**分组标记之前的全部正文行
  （例：`L113 五六月甲木…` 同时属于 五月与六月；`L741 三冬丁火微寒…` 同时属于十月／十一月／十二月）。

## 2. 结果（76 行的引文出处三分类）

| 分类 | 条数 | 含义 |
| --- | ---: | --- |
| **引文在本条已声明段落内** | **22** | 出处干净，可直接据此实现 |
| **引文在同月／同季同干、但本条未声明该段** | **50** | 引文确属该月材料，但落在本条 `sources` **之外**的续段（`或…` 段） |
| **引文落在相邻月令段** | **4** | 引文属**另一个月**的段落 |

**故 76 条里只有 22 条的引文出处是干净的**；54 条的引文不在本条声明的来源里。

### 2.1 落在相邻月令段的 4 条（逐条看过原文，不是算法漂移）

| 规则 | 主题 | 引文所在行 | 该行的实际归属 |
| --- | --- | ---: | --- |
| `QTB-M-02-12` | 十二月乙日月令取用候选 | L321 | **十一月乙木**的续段（`或成水局，壬癸两透…得一戊救方可`） |
| `QTB-M-04-06` | 六月丁日月令取用候选 | L688 | **五月丁火**的续段（`…有庚透、方无刑伤`） |
| `QTB-M-05-12` | 十二月戊日月令取用候选 | L956 | **十月戊土**的续段（`…得一己出干制癸`） |
| `QTB-M-10-11` | 十一月癸日月令取用候选 | L1821 | **十二月癸水**的续段（`或支成木局…得金出干辅救`） |

**并且 `QTB-M-02-11` 与 `QTB-M-02-12` 引的是同一句**（`得一戊救方可`，L321）——
即该句被同时挂在两个月令规则名下。至少对 `QTB-M-02-12` 是误挂：它声明的是 L323（十二月），而 L321 属十一月。

## 3. 根因（量化）

调候规则声明的是**月令的开头那一段**，而**救应句几乎都在同月的 `或…` 续段里**。实测（119 条能对上月令段的 `QTB-M-*`）：

| 项 | 数 |
| --- | ---: |
| 声明的来源覆盖其月令段**全部**正文 | **2** |
| 只声明月令段的**一部分** | **113**（缺行合计 1,125 行） |
| 对不上任何月令段 | 4 |

例：`QTB-M-01-03`（三月甲木）声明 L89 与 L99 两行，而三月甲木的续段在 L91／L93／L95／L97／L101；
它被引的救应句 `若有壬癸破火，堪作秀才` 正在 **L93**——三月甲木的续段，本条未声明。

## 4. 结论与补救次序（不跳步）

1. **76 条调候救应现在不能直接实现**：引文不在规则的来源里，据此实现等于让引擎判一条**规则自己都没引**的条款，
   而且 4 条根本引的是别的月。这与全库纪律冲突（规则↔原文必须可逐字追溯）。
2. **先补来源**（classics 侧，机械可验）：把每条 `QTB-M-*` 的 `sources`／`paragraph_ids` 补到其**月令段的续段**。
   注意同月共用：`正二月`／`五六月`／`三冬` 这类分组的续段**同属多个月**，须按分组逐段声明，不能只挂给一个月。
3. **再重跑调候普查**：补完来源后，用**本条已声明的段**重判 76 行 `has_rescue`（预期：多数仍成立，4 条相邻月的要改判或改挂）。
4. **然后才实现**：按 `shensha-rescue.ts` 的口径（前提／合取／未操作项封顶）逐条实现，引文一律取**本条已声明段内**的逐字文本。
