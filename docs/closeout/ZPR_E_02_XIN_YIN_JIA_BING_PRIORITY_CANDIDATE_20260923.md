# ZPR-E-02 辛日寅月甲丙并透的主兼入口候选（2026-09-23）

**结论**：此前 [L419 丙独透候选](./ZPR_E_02_YIN_BING_PRINCIPAL_CANDIDATE_20260923.md)留下的「甲丙兼透」空白，原书另有**辛日寅月**的直接例句。[L435](../../sources/fulltext/bazi/ziping-zhenquan/fulltext.md#L435)说「透丙化官，而又透甲，格成正財，正官乃其兼格也」；[L452](../../sources/fulltext/bazi/ziping-zhenquan/fulltext.md#L452)以同一甲丙并透例型解释财官相生、两相得。因此，在这个局部例型中，甲正财为主入口、丙正官为兼入口；不能再把「L419 前件不满足」误读成甲丙主兼完全无证据。机器候选见 [JSON](./ZPR_E_02_XIN_YIN_JIA_BING_PRIORITY_CANDIDATE_20260923.json)，运行 `python3 tools/verify-zpr-e-02-xin-yin-jia-bing-priority.py` 可复核。

## 合同边界

本候选仅对**本命**有效：日干辛，月支与月令同为寅，月藏干完整且恰为甲、丙、戊，四柱干支各有单值，本命年／月／时干出现甲和丙而**没有戊**，且四支不凑齐寅午戌会局。满足时输出两个独立入口：`ZPR-E-02:month-寅:hidden-甲:辛日正财`，局部位次「主」；`ZPR-E-02:month-寅:hidden-丙:辛日正官`，局部位次「兼」。L452 的「财官相生」只作为这一对入口的**结构例型**标签。不得由此推出任一真实出生盘已经成格、整盘纯、实际财官相生起效、吉凶、喜忌、救应或流年作用；这些全部保留信息不足。尤其 Product 的 `geju.name`、`caige.completion` 不是本源句的独立真值。

戊另透时，寅中有第三个透干入口，[L548](../../sources/fulltext/bazi/ziping-zhenquan/fulltext.md#L548)的「兼透则兼用」没有在 L435 之后给出三者主兼优先级；寅午戌全会时，L548 又说「透而又会则透与会并用」。两种形态都保持本候选**信息不足**。这里的排除是保守消费门槛，并非声称原书断定甲正财不再为主。寅巳害等其它关系不由本入口门槛改写主兼，但会使整盘作用更加不能从 L435 推断。[L349–351](../../sources/fulltext/bazi/ziping-zhenquan/fulltext.md#L349)的木日寅月禄劫另取、[L419](../../sources/fulltext/bazi/ziping-zhenquan/fulltext.md#L419)的丙独透、[L542–548](../../sources/fulltext/bazi/ziping-zhenquan/fulltext.md#L542)的杂气取清，均不能据辛日这一具体例型推广成所有日干的通用排序。

`caseState=不满足` 只否定本**辛寅甲丙清楚例型**，不否定其他主格、兼格或整个 ZPR-E-02。月支、月令、藏干或逐柱事实缺失、冲突时一律信息不足；流年干及旧产品格局标签不能补本命键。完整字段、入口 ID、冲突政策和真实日期盘在 JSON 中固定。候选尚未登记 FactKey，不进入正式 P1 manifest，不修改 ZPR-E-02 的 `rescue=unimplemented`、`verified=false`。
